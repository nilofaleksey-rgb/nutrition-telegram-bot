# AGENTS.md — постоянные инструкции проекта

Этот файл читается агентом автоматически в начале каждой сессии.

## Работа с сервером Техномикса (обязательно)

Все задачи по размещению, запуску и обновлению ботов выполняются в выделенной
среде Техномикса.

**Перед любой задачей деплоя прочитай локальный файл правил:
`docs/техномикс-правила.md`.** В нём параметры среды, порядок размещения,
управление через Supervisor и обязательные проверки.

Этот файл правил и файл контекста `docs/техномикс-контекст.md` существуют **только
локально** и исключены из Git: они содержат адрес среды. Репозиторий публичный,
поэтому параметры доступа в коммиты не попадают. Если файла правил нет — значит
настройка не выполнялась; сообщи об этом и не угадывай параметры.

Пакет доступа (приватный ключ, `known_hosts`) лежит вне проекта — в приватной папке
на этой машине, путь указан в файле правил. Содержимое ключа **никогда** не выводить
в чат, логи и не подставлять в команды буквальным текстом.

### Команды пользователя и их смысл

| Команда | Что делать |
|---|---|
| «загрузи на сервер», «выложи», «обнови бота» | Разместить проект/бота в отдельной папке на сервере, настроить программу Supervisor, запустить и **проверить фактическую работу** |
| «перезапусти», «останови», «покажи логи» | Действие только над указанным ботом |

Если проектов несколько и цель не указана — уточни только имя. Параметры сервера
повторно не спрашивай. Разрешение на уже запрошенный деплой не переспрашивай.

### Кратко о порядке работы

- Код каждого бота — в отдельной папке на сервере; конфигурация запуска — отдельным
  файлом; логи — в общем каталоге логов.
- Запуск через пользовательский Supervisor, управление командой `botctl`
  (`reread` → `update <имя>` → `status` / `start` / `stop` / `restart`).
- Массовые `restart`/`stop`/`update all` не использовать.
- Данные и `.env` существующих ботов не затирать. Изменять только целевую программу.
- `sudo`, Docker и `systemctl` в среде недоступны.
- Зависимости ставить локально: Python — в venv бота, Node — в папку бота.

### Проверка результата

Статус `RUNNING` **не** доказывает работу бота. Для Telegram обязательно:

1. `botctl status <имя>`
2. Логи без секретов
3. `getMe` с собственным токеном бота
4. Отсутствие конфликта polling (один процесс на токен)

## Секреты

Не выводить в чат и логи: приватные ключи, токены ботов, `.env`, содержимое архивов доступа.
Не коммитить их в Git. Использовать `.env` с правами `600`, загружать явно средствами
приложения (Supervisor не читает `.env` автоматически).

## Отчётность

По завершении задачи сообщить: имя бота, путь, состояние, выполненные проверки и команды
для просмотра логов / остановки / перезапуска. Сведения о размещениях сохранять **без секретов**
в `docs/техномикс-контекст.md`, чтобы следующая сессия продолжила работу.

## Проект: бот-нутрициолог (Telegram)

- Код: `src/`, запуск: `npm start`, тесты: `tests/*.test.mjs`
- Нейросети бесплатные: Google Gemini (фото/голос/текст) + Pollinations (текст без ключа) +
  локальная база продуктов. OpenAI не используется.
- Кнопка «✏️ Есть замечания» — пользовательские правки и ограничения хранятся в SQLite
  и учитываются в ответах.
- Статус и история размещений: `docs/техномикс-контекст.md`
- Деплой на Amvera больше не является целевым: рабочая среда — сервер Техномикса.
